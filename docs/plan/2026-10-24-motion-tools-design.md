# Takecraft 动作工具与主题设计

Takecraft 把用户提供的内容和动画意图变成视频。像给制作团队一张拍摄单，Agent 选择动作与风格，固定工具负责计算、排版和出片。

## 已确认目标与实施决定

用户要求优先完成可复用工具和视频质量；普通制片不应让 Agent 编写算法，Skill 包装后置。名称保留 Takecraft；用户授权在 /Users/plonguo 下选作品目录。采用 `/Users/plonguo/Takecraft Videos`，每条片独立子目录，仅作为本次交付位置，不硬编码到渲染器。沿用当前 `feat/motion-themes` 普通分支，不再新建 worktree。当前授权实施，不自动提交、推送或合并这一阶段。

本轮实现者选择：先建立动作契约，接入 Motion 14.6.0 开源核心，再提供三套完整主题和需求到项目的 compose 命令，最后制作三条实际样片并验证。初始范围是 15 秒 1080p30 的产品片；不把此配方宣称为支持任何题材的自动导演。用户尚未提供参考视频，使用原创示例继续推进，不等待参考素材。

## 制作接口

- `project.json` 仍为单条作品的事实来源，兼容 M1 清单；增加 `actions`，原始 `tracks` 作为精细调整入口保留。
- 五类动作：`enter`（一个/多个对象依次入场）、`exit`（退场）、`morph`（同一对象变形）、`reveal`（文字逐字揭示）、`focus`（镜头移动与缩放）。参数只含数据，不接受脚本。
- 通用字段 `at`、`duration`、`style`；style 为 calm / snappy / playful。enter/exit 使用 `targets`、`stagger` 和可选相对位移/缩放；morph 提供 actor 和目标属性；reveal 只允许文字；focus 可指定根对象或画布中心及 zoom。
- 编译器展开动作得到普通轨道和镜头。群组先拆成单目标事件再按实际开始时间排序，后续动作从前面已完成的状态衔接；同属性重叠拒绝，不能靠数组顺序覆盖。入场前隐藏，退场后保持隐藏。第一次入场只初始化自己控制的属性，不让后续入场改变更早画面。
- focus 不与手写 camera 混用；镜头动作互相重叠拒绝。指定对象必须是根对象，避免把嵌套局部坐标误当全局坐标。
- 校验返回规范化的原始声明，编译才物化动作；后续消费 Timeline 的阶段不再次展开。再入场恢复此前非退场动作的布局及声明的可见透明度。focus 在起点补保持关键帧，使用动作开始时的根对象中心；透明度与正尺寸由运行时限制回弹范围。
- 动作字段错误定位到 `actions.N`；展开后仍执行轨道、时间、对象和属性范围检查。

## Motion 与确定性

保留旧四种曲线的行为；新增 Motion 弹簧曲线配置。通过 spring generator 按绝对时间采样，不使用自主播放时钟。把秒统一转换为毫秒，动作结束时精确落到目标值。入场错峰使用 Motion stagger。动画不会让 Agent 编写积分、回弹公式或每帧逻辑。

缓存包含展开后的轨道、所有视觉样式、运行时代码和锁定依赖版本，Motion 升级不能复用旧视觉缓存。视频渲染、预览使用同一运行时。必须通过顺序/倒序/乱序截图一致性与同一元素跨变化的身份验证。

## 主题与简短需求

主题分别为 paper（温暖浅色、柔和圆角与横向卡片）、midnight（深色科技、明亮强调色与纵向功能列表）、editorial（大字海报、硬边框/投影、强对比构图）。主题同时管理排版、颜色、表面、圆角和动作风格，不仅换背景色。

`Brief` 包含 id、品牌、主标题、标语、2–3 个功能点、行动文案、主题，及可选本地截图/音乐路径。文案为单段、禁止手动换行，由模板自动折行。对文字长度和必填内容提供字段级错误；配方按内容长度保守选择字体大小，过量内容拒绝，不静默丢字。主题/配方是固定工具的一部分。

`compose BRIEF.json DIRECTORY [--theme NAME] --json` 读取需求，在全新目录写出可编辑 project.json 和复制后的素材；拒绝覆盖已有目录。素材相对 brief 所在目录解析，作品中的素材路径保持相对。一次 build 完成剩余生产。compose 返回路径、主题和配置统计，不在 stdout 返回整个项目或所有轨道。

`catalog --kind components|actions|themes|recipes|all --summary --json` 和 `describe action:enter / theme:paper / brief / project --json` 提供按需发现接口；旧 catalog/describe 用法保持兼容。

## 验收与边界

1. 旧清单与原有测试通过；非法动作目标、时间越界、动作与轨道冲突、焦点坐标限制有正反例。
2. Motion 数值与浏览器画面随机定位一致，起点/终点准确，跨场景保留对象身份。
3. 同一份 brief 生成三种有布局与动效差异的项目，通过字体/溢出/可见性和完整编码检查；至少一条新配方通过公开 CLI 全链路自动测试。
4. 三条 15 秒成片实际生成到作品目录，关键帧目检、技术检查通过；提供便于播放与比较的本地入口。实时听感无法实际验证时如实报告，不承诺主观“完美”。
5. 比较简短 brief 与生成项目的字节数和动作数；不把配置长度当作实际 token 节省率。
6. 补一个不依赖当前目录的 `scripts/run.mjs` 启动入口；暂不改写 Skill 或注册 `/takecraft` 命令。

不包含 React 重写、在线编辑器、自动配音、4K60、运动模糊、云服务或任意动态插件。
